## Problem Statement

维护者需要先完成 B 端管理员认证的后端能力，通过接口测试确认可用后，再决定前端的实现方式。当前后端只有工程底座：已有服务启动入口、Nacos 注册发现、MVC 网关路由、Redis 连接和基础日志配置，尚无账户业务、受控管理员创建、登录认证、共享会话、全局异常处理或统一响应实现。Nacos 配置中心尚未接入。

现有依赖声明、构建成功和历史底座冒烟记录不能证明管理员能够登录，也不能证明权限、CSRF、会话撤销或跨实例身份生效。维护者需要一套可以实际启动、通过网关调用、复现错误场景的后端交付物。

## Solution

交付管理员受控创建，以及统一的账户密码登录、当前身份查询、退出和管理员权限校验流程。管理员由部署者手动执行专用初始化命令创建，不开放管理员注册或提权接口。普通用户注册接口留到后续，但认证模型从本次起支持普通用户与管理员两种既有角色。

密码使用 Argon2id 单向摘要；认证沿用 Redis 共享 Session 和 Cookie。将全局异常处理、统一响应、SLF4J + Logback 日志关联、Nacos 注册发现与配置中心、MVC API 网关和 Redis 登录限频接入该流程。提供初始化命令、配置模板、启动说明、接口契约、自动验证及手工测试步骤，供维护者先测试后端。

## User Stories

1. As a 部署者, I want 手动执行专用命令创建管理员, so that 管理权限只能通过受控流程获得。
2. As a 部署者, I want 初始化时提供账户、密码和确认密码, so that 不需要使用公开默认密码。
3. As a 部署者, I want 创建完成后命令明确退出, so that 能通过退出码判断是否成功，且正常启动服务不会创建账户。
4. As a 部署者, I want 使用相同受控流程创建多个管理员, so that 不同维护人员可以拥有独立账户。
5. As a 部署者, I want 重复账户创建失败且不改变原账户, so that 重复执行不会覆盖密码或提升普通用户权限。
6. As a 管理员, I want 账户按统一规则校验和归一化, so that 大小写及首尾空白不会造成重复身份。
7. As a 管理员, I want 密码完整保留空白及 Unicode 字符并检查确认密码, so that 设置的密码与登录使用的密码一致。
8. As a 管理员, I want 密码以随机盐 Argon2id 摘要保存, so that 数据库不保存可直接使用的明文密码。
9. As a 管理员, I want 通过网关使用账户和密码登录, so that 获得可用于后续管理请求的会话。
10. As a 普通用户, I want 通过同一登录接口建立普通用户会话, so that 两端遵循统一身份体系。
11. As a 接口调用者, I want 登录结果包含实际角色和安全的当前身份信息, so that 后续能够按真实身份使用接口。
12. As a 接口调用者, I want 在错误账户或错误密码时收到一致提示, so that 接口不会泄露账户是否存在。
13. As a 管理员, I want 登录成功时更换会话标识, so that 登录前的会话不能固定我的登录身份。
14. As a 接口调用者, I want 获取并提交 CSRF 令牌, so that 能正确调用登录、退出等状态变更接口。
15. As a 管理员, I want 登录和退出后旧 CSRF 令牌失效, so that 身份切换前的令牌不能继续使用。
16. As a 管理员, I want 查询当前登录身份且不收到敏感字段, so that 能确认自己的账户和角色。
17. As a 管理员, I want 使用最小管理权限校验接口确认管理员身份, so that 可以在管理业务尚未实现时完成权限测试。
18. As a 普通用户, I want 管理接口拒绝我的请求, so that 登录成功不会自动获得管理权限。
19. As a 未登录调用者, I want 受保护接口返回明确的未登录响应, so that 能区分认证失效和业务错误。
20. As a 管理员, I want 退出后当前会话立即失效, so that 旧 Cookie 不能继续访问受保护资源。
21. As a 管理员, I want 退出当前会话时保留其他独立登录会话, so that 多设备会话具有明确边界。
22. As a 管理员, I want 会话闲置 30 分钟后失效, so that 长期无人使用的登录不会持续有效。
23. As a 管理员, I want 切换服务实例后仍能识别同一有效会话, so that 认证不依赖单个进程内存。
24. As a 平台维护者, I want 每个受保护请求核对当前账户状态和认证版本, so that 旧角色快照不能绕过账户失效。
25. As a 平台维护者, I want 并发旧请求不能恢复已退出或撤销的会话, so that 会话撤销在竞争条件下仍然成立。
26. As a 平台维护者, I want 按账户和来源地址分别限制连续登录失败, so that 批量尝试密码受到限制。
27. As a 被限频的调用者, I want 获得明确的可重试时间, so that 可以判断何时重新登录。
28. As a 接口调用者, I want 参数、认证、权限、限频及系统错误采用一致响应结构, so that 测试工具和后续前端能统一处理结果。
29. As a 接口调用者, I want 网关失败也提供真实 HTTP 状态及可关联的错误信息, so that 不会把路由或下游故障误认为业务成功。
30. As a 平台维护者, I want 网关和用户服务记录相同请求标识, so that 可以追踪一次登录请求经过的服务。
31. As a 管理员, I want 日志和错误响应不泄露密码、摘要或会话凭证, so that 排错不会暴露认证秘密。
32. As a 部署者, I want 服务通过 Nacos 注册发现并读取外置配置, so that 路由和配置不依赖复制本机临时配置。
33. As a 部署者, I want 获得不包含真实凭据的配置模板与导入步骤, so that 能复现本地启动并区分开发、部署环境。
34. As a 平台维护者, I want Redis 或用户身份核验不可用时受保护请求失败关闭, so that 基础设施故障不能变成绕过权限的机会。
35. As a 平台维护者, I want 伪造身份头、转发头及内部路径访问不能绕过认证, so that 网关与业务服务共同维护安全边界。
36. As a 接口测试者, I want 获得初始化、CSRF、Cookie、登录、查询、退出及错误示例, so that 无需等待前端就能验收后端。
37. As a 项目维护者, I want 明确记录实测结果与未验证限制, so that 构建、底座检查和业务验收不会混为一谈。

## Implementation Decisions

- 本次只实现后端。术语沿用共享领域词汇表：管理员与普通用户是角色，禁用是独立账户状态；不引入超级管理员、教师或审核员角色。B/C 是应用边界，不是两套账户体系。
- 用户服务拥有账户、密码摘要、角色、状态、认证版本及本次认证审计。网关不持有业务数据库凭据；服务之间不依赖彼此的可执行模块、不共享实体或跨库读写。
- 业务按 interfaces → application → domain 组织，基础设施适配数据库、Redis、密码组件和必要的内部 HTTP 协作。保持现有 Java 21、Spring Boot/Cloud/Alibaba 版本管理方向，补充依赖须通过实际构建与运行验证。
- common-core 承载无框架依赖的统一响应、通用错误协议及必要基础类型。MVC、Security、Redis、日志过滤器等装配留在所属服务或确有复用必要的专用模块，显式导入；不扩大扫描范围或把框架配置塞入 common-core。
- 管理员创建采用部署者手动执行的专用命令或专用初始化运行模式；与正常 Web 服务启动分离。账户、密码和确认密码由受控输入提供，不硬编码、不输出密码、不要求将密码写入会被提交的配置或命令行参数。成功退出码为零，输入、冲突和运行失败返回非零退出码。
- 同一流程允许创建多个管理员。账户为 4～32 位 ASCII 字母、数字或下划线，去首尾空白并小写归一化后唯一，注册后不可修改。数据库唯一约束保证并发创建不会绕过唯一性；大小写差异、空白差异或已有普通用户的同名账户均导致冲突，不覆盖密码、不升级角色。
- 密码为 8～64 个 Unicode 码点，不去除空白、不截断；创建时确认密码必须一致。使用 Spring Security Argon2PasswordEncoder 实现 Argon2id，并引入其所需的 Bouncy Castle。每次编码生成随机盐，保存算法标识、参数、盐和摘要，接口不返回摘要。具体内存、迭代及并行参数经运行环境测量确定，记录参数及耗时证据，不宣称尚未测量的性能。
- 用户服务通过正式数据库迁移建立账户、必要撤销事实和认证审计的持久化结构，启用并验证此前在本地关闭的迁移能力。账户状态、角色和 authEpoch 等持久事实不能只存在 Redis。不得覆盖或清空已有数据库材料。
- 接口统一使用既有 /api/v1 前缀。提供 POST /auth/login、POST /auth/logout、GET /auth/csrf、GET /users/me。增加最小 GET /admin/users/me，返回当前管理员的安全身份信息，用于手工验证管理员权限；不借此实现用户列表或账户管理业务。
- 登录接口以 JSON 接收 account、password，角色由数据库决定。普通用户提交正确凭据也能建立普通用户会话。登录与当前身份响应仅包含必要的用户编号、规范化账户、角色等安全字段，身份响应禁止缓存。拒绝客户端指定角色或覆盖认证版本。
- Spring Security 负责认证授权。网关和用户服务采用 Spring Session Redis indexed repository，共享 BJSESSION Cookie、Path=/、Redis 命名空间、30 分钟闲置时限及兼容序列化契约。Session 仅保存最小身份，不保存业务实体、密码摘要或联系方式；跨服务类型与序列化必须可兼容。
- 登录成功轮换会话标识；当前已登录身份切换账户需先退出。退出仅撤销当前会话，清除客户端会话 Cookie；其他独立会话保持有效。持久身份版本检查和必要的会话撤销判定必须阻止并发旧请求保存后恢复已撤销身份。具体撤销存储与保留策略须随实现给出可复现证据。
- 每个受保护请求同时核验会话和当前账户状态/authEpoch。用户服务通过本服务权威存储核验；网关如需远程核验，采用既定的服务发现和内部 HTTP 协作，凭据由受控环境提供。不得依赖延迟失效的正向身份缓存。用户服务或 Redis 无法完成必需校验时拒绝受保护操作。
- 生产环境 HTTPS，Session Cookie 为 HttpOnly、Secure、SameSite=Lax；本地回环 HTTP 采用显式独立配置。状态变更接口启用 CSRF；先获取令牌，再通过约定请求头提交。登录和退出清理旧令牌，调用者需要重新获取。禁止任意来源 CORS。
- 不存在账户与密码错误使用统一提示。按归一化账户标识和可信来源地址分别累计失败；任一维度在 15 分钟内达到 10 次失败后，后续登录受限 15 分钟，并通过响应明确可重试时间。Redis 计数和限制判定必须具备并发正确性；计数键不能暴露明文凭据。不得信任客户端任意提交的转发地址作为限频来源。
- 统一响应包含 code、data、message、requestId、serverTime，只有 code=0 表示业务成功。实现期间在接口文档冻结本次所需数值错误码、字段白名单、时间格式和示例。HTTP 400/401/403/404/405/409/429/5xx 保留实际语义，不能把失败统一包装为 HTTP 200。
- 未登录或会话失效访问受保护资源返回 401；已认证普通用户访问管理资源返回 403；CSRF 拒绝返回 403；输入无效返回 400；账户创建冲突以明确失败及非零命令退出码体现；登录限频返回 429 及可重试信息。区分认证失败、账户状态拒绝和系统不可用，同时避免泄露不应公开的账户事实。
- 全局异常处理覆盖 MVC 参数校验、JSON 解析、业务异常、未知异常；Security 的认证、授权、CSRF 拒绝及网关路由/下游失败另有对应错误出口，最终遵循同一响应契约。错误响应不返回堆栈、SQL、内部地址或凭据。
- 日志沿用 SLF4J + Logback，补结构化输出、请求标识生成及网关到用户服务的传播、MDC 清理、合理异常级别和必要认证事件。认证审计由用户服务持久保存；不建设审计查询页面。日志与审计均不得包含密码、摘要、完整 Session/CSRF/服务凭据或未经控制的请求体。
- 沿用 Gateway Server Web MVC、LoadBalancer 和显式服务路由，不引入 WebFlux。网关及用户服务分别执行自己的安全责任；禁止公开 internal、下游 Actuator 或按服务名自动映射全部接口。清理伪造身份头、内部认证头及不可信转发头，业务服务不以用户身份头代替会话认证。内部调用使用独立受控身份和私网边界，管理员浏览器身份不能调用内部接口。
- Nacos 本次同时包括注册发现和配置中心。沿用 spring.config.import，补 Config 依赖、环境/Data ID/Group 组织、非敏感配置模板及导入步骤。启动连接信息及真实凭据由受控环境或文件提供。至少通过网关和用户服务证明实际读取了配置；记录必需配置缺失、连接失败、有效本地缓存及运行中断连的实际行为，避免配置读取失败后静默使用不安全默认值。不额外承诺所有配置动态热更新。
- Redis 承载共享 Session 和临时登录限频；连接成功或 PING 不能代替这些业务能力通过。沿用现有本地基础设施版本与持久化方向，不额外引入 Redis 或 Nacos 集群。
- 完成后提供依赖启动与停止、Nacos 配置导入、迁移、管理员初始化、接口调用和排错说明。接口示例须说明 Cookie 保存、CSRF 请求头、登录/退出后令牌刷新、经网关调用的地址及错误响应。

## Testing Decisions

- 采用用户已确认的一个主要行为测试边界：从 API 网关发起真实 HTTP 请求，联通真实用户服务、MySQL、Redis 和 Nacos。管理员初始化命令作为同一验证流程中的账号准备入口，并单独断言它的可观察输出、退出码和重复执行结果。
- 好的测试只断言外部行为：命令是否成功、HTTP 状态与业务码、字段白名单、Cookie/CSRF 变化、跨实例身份、限频及故障结果。避免以 Controller/Mapper 调用次数、私有方法或某个实现类的存在作为验收。
- 沿用现有依赖启动、服务运行和网关冒烟材料，扩展业务场景；现有仓库没有认证测试类，不能宣称已有类似测试覆盖。构建、基础设施连接、网关转发和认证验收分别记录结果。
- 创建流程验证：有效创建、多个管理员、确认密码不一致、账户与密码边界、Unicode 码点和密码空白、大小写/空白归一化冲突、已有普通用户同名冲突、并发重复创建、重复执行不改变密码/角色，以及正常服务启动不创建管理员。
- 密码存储验证：持久化结果为 Argon2id 摘要；相同密码多次创建得到不同摘要；原密码可验证、错误密码失败；API、日志和命令输出不包含明文或摘要。仅此存储安全性质在数据库适配边界补充检查，不为内部方法另建测试体系。
- 主流程验证：获取 CSRF、管理员登录、查询当前身份、访问最小管理员入口、退出、旧 Cookie 再访问被拒；独立会话退出互不影响。会话标识在登录时轮换，登录前标识不可获得登录后身份。
- 权限验证：游客 401、普通用户管理请求 403、管理员允许；伪造角色/用户/内部认证/转发头不获得权限；直连用户服务仍执行认证授权；公开网关不开放内部或下游管理路径。普通用户、禁用状态及认证版本变化由受控测试夹具准备，不新增公开注册或禁用接口。
- CSRF 验证：缺失、错误、身份切换前的旧令牌均被拒绝；登录/退出后重新获取令牌可继续合法流程。检验 Cookie 的作用域、HttpOnly、SameSite、生产 Secure 与本地显式覆盖，以及身份响应不缓存。
- 限频验证：账户与来源地址两个维度各自计数，不同账户不能绕过来源限制，不同来源不能绕过账户限制；第 10 次失败后的后续请求受限；429 和重试信息正确；并发请求不能绕过阈值，伪造转发头不能任意更换计数来源。使用可控时间或受控测试配置验证窗口，保留生产默认规则的配置断言，避免依赖长时间 sleep。
- 会话验证：至少两个用户服务实例及共享 Redis，经同一 Cookie 跨实例访问；闲置失效；退出与并发保存竞争；账户状态或 authEpoch 改变后下一次受保护请求拒绝；恢复账户状态也不能复活旧会话。
- 故障验证：Redis 或身份核验服务不可用时受保护操作失败关闭；下游不可用返回真实网关错误；Nacos 配置读取、服务发现及恢复有实际证据。不为测试删除现有持久数据或复用生产凭据。
- 统一响应与日志验证：业务错误、参数错误、Security 拒绝、网关失败、未知异常都符合约定；同一请求在网关、用户服务和响应中可关联；并发请求之间不串 MDC；日志和响应不泄露敏感信息。
