## Problem Statement

管理员已经能在 B 端登录、查询题库、查看详情、新建和删除未发布草稿，但尚不能通过页面补全题面、说明、难度、标签和资源限制。后端已经提供完整字段保存及修订冲突接口，前端编辑入口仍禁用，管理员无法完成创建后继续维护题目的基本流程。

长题面编辑还会遇到多人竞争、刷新、会话失效和保存响应丢失。如果页面只补一个保存按钮，可能覆盖他人修改、丢失本地内容，或将结果未知误报为保存失败或成功。管理员需要能够分辨服务器保存与标签页暂存，并在异常后明确选择下一步。

## Solution

提供管理员专用的独立题目草稿编辑页，从题库列表或详情进入，也可直接访问和刷新。支持完整草稿字段编辑、手动保存、基础 Markdown 安全预览和只读测试数据清单。

保存使用草稿修订号防止静默覆盖；发生竞争时保留本地输入，逐字段对照服务器内容，由管理员选择合并结果后再次手动保存。当前标签页在输入变化后 1 秒内暂存未保存内容，刷新及同账户重新登录后提示恢复；保存结果不确定时先回读服务器，不盲目重复提交。

本切片交付可真实维护且能保护输入的草稿编辑流程，不包含测试数据上传、发布校验、题目版本创建或发布/下架。

## User Stories

1. As an 管理员, I want 从题库列表进入指定题目的编辑页, so that 可以继续维护已创建的草稿。
2. As an 管理员, I want 从只读详情进入编辑页, so that 查看和修改能够自然衔接。
3. As an 管理员, I want 直接访问编辑地址或刷新后加载同一题目, so that 不必重复查找题目。
4. As an 管理员, I want 看到题号、草稿修订号和服务器更新时间, so that 能识别正在维护的对象与基线。
5. As an 管理员, I want 修改标题、题面、输入说明和输出说明, so that 可以逐步补全题目内容。
6. As an 管理员, I want 维护难度及最多五个标签, so that 题目能够分类和检索。
7. As an 管理员, I want 使用明确单位维护 CPU、墙钟和内存限制, so that 不会误填资源配置。
8. As an 管理员, I want 保存内容尚不完整的草稿并清空可选字段, so that 可以分阶段完成出题。
9. As an 管理员, I want 就近查看字段错误且保留合法输入, so that 修正错误无需重新填写。
10. As an 管理员, I want 获知题面和说明的实际 UTF-8 字节限制, so that 中文和 emoji 不会造成错误的长度判断。
11. As an 管理员, I want 使用 Markdown 编写题面和说明并预览, so that 可以表达代码块、列表和表格。
12. As an 管理员, I want 在窄屏切换源文与预览, so that 长内容仍能编辑和检查。
13. As an 管理员, I want 查看已有样例及隐藏测试数据的清单元信息, so that 知道当前草稿绑定了哪些数据。
14. As an 管理员, I want 主动点击保存并区分保存状态与本地暂存状态, so that 清楚哪些内容已经在服务器生效。
15. As an 管理员, I want 无修改时不能重复保存, so that 不产生无意义的修订变化。
16. As an 管理员, I want 保存期间阻止重复提交和继续编辑, so that 成功提示不会误覆盖请求之后输入的内容。
17. As an 管理员, I want 保存成功后留在原页并回读最新修订, so that 能继续编辑并确认持久化结果。
18. As an 管理员, I want 保存冲突时保留全部本地输入, so that 多人编辑不会使我的工作丢失。
19. As an 管理员, I want 逐字段对照本地与服务器内容并选择采用哪份, so that 能明确决定最终合并结果。
20. As an 管理员, I want 合并完成后检查表单并手动保存, so that 冲突处理不会未经确认覆盖服务器。
21. As an 管理员, I want 再次竞争时仍收到冲突提示, so that 人工合并不会绕过并发保护。
22. As an 管理员, I want 即使只改变测试数据清单也提示修订变化, so that 不会忽略草稿绑定数据的变更。
23. As an 管理员, I want 网络中断后先确认服务器内容, so that 不会盲目重复提交可能已经成功的保存。
24. As an 管理员, I want 无法确认结果时保留内容并可重试查询或复制, so that 不会被错误的成功或失败提示误导。
25. As an 管理员, I want 输入后自动在当前标签页暂存, so that 刷新时有机会恢复未保存内容。
26. As an 管理员, I want 恢复前先检查当前身份及服务器修订, so that 旧暂存不会覆盖他人新修改。
27. As an 管理员, I want 暂存与服务器修订不同时进入相同冲突流程, so that 恢复过程也遵守并发保护。
28. As an 管理员, I want 离开有未保存内容的页面前收到提醒, so that 能决定是否继续编辑。
29. As an 管理员, I want 登录过期后由我选择重新登录并返回编辑位置, so that 不会因自动跳转丢失输入。
30. As an 管理员, I want 同账户重新登录后确认恢复且不自动保存, so that 重新认证不会隐式执行旧命令。
31. As an 管理员, I want 主动退出或切换账户时清除旧账户编辑内容, so that 不会向其他账户展示受保护草稿。
32. As an 管理员, I want 暂存不可用时仍能手动保存并复制全部编辑内容, so that 浏览器存储异常不阻断出题。
33. As an 管理员, I want 剪贴板不可用时仍有可选中文本, so that 可以自行保留工作成果。
34. As an 管理员, I want 题目被删除或权限失效时停止提交并保留同账户已加载输入供复制, so that 不会反复失败或意外创建新题目。
35. As an 管理员, I want 初次加载失败时看到明确错误和返回入口, so that 不会误把空白表单当作可保存草稿。
36. As an 管理员, I want 预览不会执行题面中的 HTML、危险链接或加载图片, so that 查看源文的效果符合约定。
37. As an 管理员, I want 返回题库时保留原有列表筛选和分页体验, so that 编辑不会干扰现有管理流程。
38. As an 管理员, I want 键盘可达的控件、明确标签及可见错误, so that 可以稳定完成编辑与保存。
39. As an 普通用户或未登录访问者, I want 编辑入口和接口正确拒绝无权限操作, so that 草稿及隐藏数据不会泄漏。

## Implementation Decisions

### D1 范围与模块边界

- 沿用现有 Vue、TypeScript、Pinia、Vue Router、shadcn/vue 和全局主题；只调整 B 端题库入口、编辑页、请求适配、必要的会话返回及暂存清理链路。
- 增加管理员路由 `/problems/:id/edit`，部署基址仍为 `/admin/`。现有只读详情抽屉继续保留。
- 不修改后端业务、数据库结构、服务边界、共享会话 ADR 或发布流程；不引入新的公共抽象层。
- 领域概念使用题目、题目草稿、草稿修订号、题目版本和测试数据。草稿修订号不称为发布版本号。

### D2 表单与字段契约

- 编辑字段固定为 title、statement、inputDescription、outputDescription、difficulty、tags、timeLimitCpuMs、timeLimitWallMs、memoryLimitMiB。题号等身份、元信息及测试数据清单不可编辑。
- 标题去首尾 Unicode 空白后为 1～100 个码点；标签最多 5 个，每个去首尾空白后为 1～20 个码点，不自行增加去重规则。
- 题面和两项说明原文保留，合计不超过 102400 个 UTF-8 字节。无内容的文本框发送 null，不对非空题面做 trim；难度未选、数字未填发送 null，标签无值发送空数组。
- CPU 100～10000 ms、墙钟 100～30000 ms、内存 64～2048 MiB，数字为整数；CPU 和墙钟均有值时墙钟不得小于 CPU。资源允许分别留空，不要求草稿字段齐全。
- 脏状态、回读同步和差异比较采用一致的字段规范化，避免 null 或空输入及标题、标签规范化产生假差异。
- 前端字段错误就近展示；后端校验错误没有结构化字段清单时显示表单级提示及 requestId，不依赖解析英文错误消息。

### D3 手动保存与请求状态

- 业务请求通过现有网关 `/api/v1/**`，携带真实会话；写请求获取并发送有效 CSRF 头，不使用伪造身份头。
- GET `/api/v1/admin/problems/{id}` 加载当前详情；PATCH `/api/v1/admin/problems/{id}/draft` 始终提交完整可编辑字段集和 expectedRevision，可空字段不省略。
- 没有修改时禁用保存；保存中固定请求快照及修订号，禁用编辑和重复提交。成功使用服务端返回的完整详情更新基线、修订和只读清单，清理该题暂存，留在当前页。
- 服务器保存与本地暂存状态独立；暂存成功不能显示为服务器已保存。400 等明确拒绝保留输入并解锁。
- 网络异常、响应损坏或无法判断写入结果时显示“保存结果待确认”，先回读，不自动重放。不能仅凭 5xx 断言写入没有发生。
- 回读字段与冻结请求规范化内容一致则更新基线并提示“已与服务器同步”，不宣称该次请求必然成功；内容不同但修订未变则解锁供人工重试；内容不同且修订已变进入冲突对照。
- 待确认回读失败时保留内容、继续禁用保存和编辑，允许复制、重新确认结果或经提醒离开。刷新恢复后也必须先读取服务器再决定后续动作。

### D4 并发冲突

- 409 / 40910 保存冲突返回最新草稿。保留本地字段，逐字段展示本地与服务器内容；长文本对照展示原文。
- 每个不同字段必须显式选择本地或服务器值。题面及两项说明分别按整个字段选择，标签整体选择，资源分别选择且合并后重新校验联动；不做逐行自动合并。
- 差异处理完成后回到表单供检查，以所查看的服务器详情为基线；合并后的修改必须再次手动保存，携带所查看的修订。再发生竞争继续执行相同流程。
- 合并结果等同服务器则提示已同步，不增加无意义保存。只有测试数据清单等元信息变化时也展示变化并要求确认修订，不静默换修订号。
- 取消对照保留输入和冲突状态；采用服务器内容并放弃本地修改需要明确确认。

### D5 标签页暂存与恢复

- 使用当前标签页的 sessionStorage，按 userId 和 problemId 隔离，保存格式版本、题目或草稿身份、基线修订及本地字段，不保存认证凭据。
- 输入变化后 1 秒内暂存；站内离开、刷新和登录跳转前尽力立即写入，不依赖只有防抖到期才写入。
- 恢复前重新获取当前管理员身份及服务器详情；同修订提示恢复或放弃，不同修订进入字段对照，不直接将旧输入套到新修订号。
- 本地与服务器内容相同则提示已同步并清理冗余暂存；草稿身份不同则不直接恢复，提示不兼容并允许同账户复制。损坏或不兼容格式不能提交。
- 普通站内离开需提醒，确认离开后保留可用暂存；明确放弃、成功保存、主动退出或识别到账户改变时清理对应内容。退出或切换账户还须清理内存状态并忽略迟到请求，防止旧内容重新出现。
- 暂存不可用时持续提示，仍允许编辑与手动保存，提供复制全部编辑字段及题号和可选中文本；复制不包含认证信息。浏览器离开提醒尽力使用，不承诺关闭标签页、崩溃或系统终止后恢复。

### D6 身份、权限与离开处理

- 初次加载失败展示错误与返回入口，不呈现空白可保存表单。加载完成前不得展示其他账户暂存。
- 401 保留输入、尝试暂存、显示重新登录入口；管理员点击后携带返回位置进入登录页。同账户返回后提示恢复，不自动提交；其他账户登录清除旧内容。
- 暂存失败时不直接跳转，先提示并允许复制。403 / 40300 不视为会话过期无限重定向；403 / 40301 更新 CSRF 后只允许人工重试，不自动重放写请求。
- 编辑中 404 或管理员权限失效停止保存和自动重试；同账户已加载输入保留供复制，不自动另建题目。初次无权限不得读取草稿。
- 保存期间阻止普通站内跳转；主动退出需明确确认后执行，并遵守清理规则。刷新或关闭使用浏览器离开提醒。

### D7 Markdown 与页面交互

- 题面、输入说明、输出说明支持源文和本地安全预览；基础语法包括标题、段落、列表、引用、代码块、表格和普通链接。窄屏可切换编辑与预览。
- 原始 HTML 转义显示；链接只允许 http/https，拒绝脚本或 data 等地址，新窗口隔离 opener。图片仅显示占位，不产生图片请求；不加载隐式嵌套图片，不使用外部渲染服务。
- 选择成熟 Markdown 解析器并对白名单输出清理，不自行实现解析器；具体包和补丁版本在实现时选择。代码块按文本显示，不要求语法高亮。
- 源文继续以既有普通字符串存储；C 端后续应遵守相同内容约定，本次不修改 C 端及既有数据。
- 页面显示明确题号、草稿修订号、更新时间、保存状态和暂存状态；基本信息、题面及说明、资源限制分区。保留现有列表筛选和分页体验、键盘可达性与明确输入标签。

## Testing Decisions

### 测试边界与已有基础

- 以用户在浏览器中的完整编辑流程为主要验收边界，通过真实网关连接现有认证及题目接口，验证可观察行为；不按组件私有状态、内部方法调用次数或存储键名验收。
- 现有后端已用 ProblemDraftFlowTest 从真实网关 HTTP 验证草稿生命周期、revision CAS、认证及测试数据登记。复用这些既有接口和行为作为前端联调基础，不复制后端业务实现。
- 测试覆盖 B 端题库入口、编辑、保存、冲突、恢复、登录返回和清理以及 Markdown 预览；优先从同一浏览器流程验证，避免分别为内部辅助模块建立多套模拟模型。
- 网络未送达、提交后响应丢失、回读失败等在请求边界模拟；存储不可用、剪贴板不可用等使用浏览器可控故障或替代环境验证。不得以模拟响应替代真实接口成功路径。
- 字段边界、请求完整字段集、CSRF、权限拒绝及修订变化最终仍以真实接口行为为准。既有 ProblemDraftFlowTest 覆盖的后端规则不重复建设第二套业务测试。

### 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 创建后进入编辑、保存、刷新及直接地址打开 | 字段从真实接口回读一致；题号固定，保存成功修订递增 |
| 不完整草稿及各项空值 | 允许保存，完整请求字段正确，不误触发布规则；无改动不发保存 |
| 内容边界 | 标题和标签码点、中文及 emoji 的 UTF-8 合计边界、资源上下限及墙钟联动正确 |
| 双页面同时编辑 | 第二次保存 409，原输入保留，每个不同字段可选，确认前不发重试 |
| 仅文件清单变动及重复竞争 | 提示最新修订并确认；确认后再次竞争仍受 CAS 保护 |
| 保存中的连续点击和编辑 | 请求不重复，表单冻结；返回内容不误覆盖后续输入 |
| 请求未到服务端、写入成功但响应丢失、回读失败 | 分别进入可重试、已同步、待确认状态，不盲目重放 |
| 刷新恢复且服务器未变或已变化 | 同修订提示恢复，不同修订进入对照；不静默覆盖 |
| 登录过期及同或不同账户重新登录 | 正确返回，按账户隔离恢复，切换账户不显示旧内容 |
| 暂存和剪贴板不可用 | 持续提示，可手动保存及选择文本；不自动丢弃输入或跳转 |
| 路由离开、刷新、主动退出及迟到请求 | 提醒符合规则，退出清理，迟到响应不恢复旧账户内容 |
| 编辑途中 404 或 403 与初次加载失败 | 停止保存，已加载输入可复制；初次失败不呈现空白可保存表单 |
| Markdown 代码、表格、HTML、危险链接与图片 | 基础语法可读，原始 HTML 不执行，危险链接不可用，无图片请求 |
| 页面质量 | 保留列表筛选与分页，键盘可达、标签明确，窄屏能编辑和预览，错误可见 |

验证执行现有类型检查与构建；lint 使用不自动修复的受影响文件检查。前端当前没有测试脚本，具体浏览器行为测试工具在实现计划中选定，不将新增完整测试平台作为功能前提。

## Out of Scope

- 测试数据上传、替换、删除、排序及槽位维护；编辑页只读展示已有清单。
- 发布校验、校验执行、校验状态、题目版本创建、发布、下架、删除已发布题目及 C 端公开投影。
- 判题执行器、提交服务、竞赛冻结快照及任何后端业务或数据库改动。
- Markdown 公式、图片上传或远程图片加载、富文本工具栏、语法高亮、原始 HTML 白名单扩展。
- 跨标签页或跨设备编辑暂存、关闭标签页或崩溃后的恢复保证。
- 自动保存到服务器、自动合并差异、自动重放写请求、自动创建新题目或自动改变修订号。
- C 端 Markdown 渲染实现及既有内容批量迁移。
