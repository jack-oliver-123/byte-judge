# 图片范围补充调研

调研日期：2026-11-02。用途：根据用户提供的功能树，补充竞赛、站内消息、独立运行及定时任务管理的需求依据，支持更新 [01.需求文档.md](./01.需求文档.md) 和 [02.需求规格说明书.md](./02.需求规格说明书.md)。

## 1. 方法与证据边界

本次实时查阅 DOMjudge 官方手册、洛谷官方帮助、HOJ 维护者文档及仓库、LeetCode 官方帮助和 Spring Framework 官方文档。仅记录来源明确陈述的能力；没有进行注册后全流程体验、开源平台部署、真实用户访谈或性能测试。DOMjudge `main` 文档会随开发更新，需求采用其机制作为参考，不声称项目与该版本实现一致。

图片决定本项目本期功能范围。官方资料用于补全业务规则，不用于把图片已经要求的竞赛或独立运行继续降为可选功能。下文“项目选择”是面向本科毕设的自主规格，不等于各平台共同规则。

## 2. 官方依据与需求启发

### 2.1 竞赛状态与受理时间

DOMjudge 区分比赛可见、开始、结束及可选封榜等时间点，并明确起点生效、终点不包含。例如 12:00 开始、17:00 结束时，17:00 已不能按正常赛时提交。[来源：DOMjudge 比赛配置](https://www.domjudge.org/docs/manual/main/config-basic.html)

**项目选择**：公开比赛按服务端时间计算“未开始 / 进行中 / 已结束”，正式受理区间采用 `[startTime, endTime)`。前端倒计时和后台定时任务不能代替服务端实时校验。赛时受理、赛后才完成评测的提交，仍归属正式赛时提交；不能因判题排队跨过结束时间而改为练习提交。

### 2.2 报名规则并不统一

洛谷公开比赛规则允许个人用户在比赛结束前报名，并说明报名后不能取消；这表明“必须开赛前报名”并非成熟 OJ 的统一规则。[来源：洛谷公开比赛参赛规则](https://help.luogu.com.cn/rules/community/contest-participation)

**项目选择**：按图片“未开赛显示报名按钮，开赛后未报名显示未报名”的交互，采用开赛前截止报名。已登录正常用户仅能在已发布且尚未开赛时报名，重复报名幂等；开赛后未报名用户不能进入正式答题。该选择不同于洛谷的晚报名规则，应在规格中明确说明，避免误写成调研结论。

### 2.3 ACM 计分、罚时及并列

洛谷官方说明 ICPC 模式按通过题目数降序、总耗时升序排名，并列明错误提交的 20 分钟罚时。[来源：洛谷比赛说明](https://help.luogu.com.cn/manual/luogu/contest)

DOMjudge 默认每题 1 分，按总分降序、罚时升序排序，可按最后一次通过的时间继续破同分；其配置将错交罚时默认设为 20 分钟，只有最终解出的题累加错交罚时，编译错误默认不罚。[来源：DOMjudge 排名说明](https://www.domjudge.org/docs/manual/main/scoring.html)、[计分配置](https://www.domjudge.org/docs/manual/main/conf_ref.html)

**项目选择**：个人 ACM 模式，每题 1 分；按通过题数降序、总罚时升序、最后一个首次 AC 的提交时间升序比较。某题罚时为从开赛到该题首次有效 AC 受理时间的完整分钟数，加此前有效 WA/TLE/MLE/RE/OLE 次数 × 20；CE、SE、独立运行和赛后练习不罚。未通过的题不计入总罚时，首次 AC 后的重复提交也不加罚。若这些指标仍相同，使用用户编号稳定展示，名次是否并列应在规格中统一确定。无封榜、滚榜、Rating 或 OI 部分分。

### 2.4 赛后练习与正式榜单分离

HOJ 维护者 README 的更新记录说明增加了“允许比赛结束后提交”的能力；官方比赛文档还说明赛制、公开/保护/私有权限和后台比赛管理。因此成熟系统会分别设计时间、访问权限及提交规则，不能只给比赛加一组题目。[来源：HOJ 官方仓库](https://github.com/HimitZH/HOJ)、[HOJ 比赛介绍](https://docs.hdoi.cn/use/contest/)

DOMjudge 重判保留原提交时间并重新运行；可先创建新评测集合再应用或取消。这说明历史榜单修正与新练习提交是不同操作。[来源：DOMjudge 评测与重判](https://www.domjudge.org/docs/manual/main/judging.html)

**项目选择**：已发布历史竞赛向正常登录用户开放赛后练习，不要求当年已报名；练习使用该场冻结的题目版本，单独标记上下文，不进入正式竞赛榜。比赛结束只停止新正式提交，不阻止已受理正式提交产生结果。正式榜允许随这些结果及管理员对原正式提交的重判进行正确修正；“赛后不改榜”只能指赛后练习不改正式榜，不能把结果未完成时的临时榜永久冻结。

### 2.5 独立运行与正式提交是不同动作

LeetCode 2024 年官方帮助说明，Run 使用用户在测试区选择或修改的用例；Submit 则使用系统全部测试用例验证。该资料可支持“独立运行”和“正式评测”的需求区分，不用于照搬 LeetCode 的函数签名模式。[来源：LeetCode 自定义测试帮助](https://support.leetcode.com/hc/en-us/articles/32442719377939-How-to-create-test-cases-on-LeetCode)

**项目选择**：题库、比赛内及赛后练习均提供“运行”与“提交”两个入口。运行只使用公开样例或用户自定义输入，在同样受限的环境中编译执行；返回实际输出、错误及资源信息，不读取隐藏数据、不给 AC/WA 的正式结论、不计提交数或罚时。正式提交才使用题目全部预设数据。运行仍需登录、限频、隔离和数据归属校验，避免成为绕过正式提交限额的入口。

### 2.6 站内消息

HOJ 官方 README 声明拥有站内消息系统，更新记录列出评论、回复、点赞及系统通知等消息类别。[来源：HOJ 官方仓库](https://github.com/HimitZH/HOJ)

**项目选择**：仅实现图片要求的本人消息列表、查看、删除；为使功能有实际来源，接收报名确认、竞赛撤销、管理员重判结果等系统通知。查看可标记已读，删除只影响当前收件人的可见记录，不删除业务事实或审计。消息生成/重试应按事件和收件人去重，不扩展为用户私信、群聊或邮件短信。

### 2.7 定时任务能力及多实例边界

Spring Framework 6.2 官方文档定义 TaskScheduler，支持一次性、固定频率、固定间隔及 Trigger 调度；CronTrigger 使用 Cron 表达式，Spring Cron 为含秒的六字段格式，允许指定解析时区。官方同时提醒重复初始化或多个调度声明可能导致重复执行。[来源：Spring Framework 6.2 任务调度](https://docs.spring.io/spring-framework/reference/6.2/integration/scheduling.html)

**项目选择**：后台支持任务列表、新增、修改、删除、启停及执行记录，采用六字段 Cron 和 Asia/Shanghai 时区，限制最小执行间隔。处理器只允许系统预定义业务操作和受校验参数，禁止管理员输入任意脚本、Shell、SQL、类名/方法名或外部 URL。

TaskScheduler 本身不代表已经具备持久任务管理、授权、审计或多节点防重。本项目应另行要求持久配置、多实例同一计划触发唯一有效执行权、失败记录与有界重试。比赛是否开始/结束应直接以服务端时间判断；任务只负责提醒、刷新或补偿，关闭一个管理任务不得让比赛一直保持未开始，或取消判题的硬性恢复保障。

## 3. 必须明确的项目决策

| 议题 | 建议的确定规则 | 与证据的关系 |
| --- | --- | --- |
| 推荐竞赛 | 已发布、未结束竞赛按开始时间升序、竞赛编号升序稳定展示；不声称个性化推荐 | 图片功能的最小可行解释，自主选择 |
| 报名截止 | 仅开赛前可报名，开赛后的未报名用户提示未报名 | 自主选择；不同于洛谷允许晚报名的规则 |
| 题目快照 | 发布时绑定经过校验的题目版本，开赛后不得修改参赛题目和计分配置 | 保证本项目复现及公平性，不称为所有平台行为 |
| 正式受理时间 | `[开始, 结束)`，以持久化受理的服务端时间判断 | 与 DOMjudge 时间边界一致 |
| 赛后榜单 | 赛后练习不改榜；赛时受理任务的迟到结果、原正式提交重判可修正正式榜 | 避免把“赛后不改榜”写成不可完成的冻结规则 |
| 运行结论 | 正常运行仅代表当前输入执行完成，不能当成通过全部测试 | 依据 Run/Submit 区分再具体化 |
| 定时任务安全 | 白名单处理器、参数校验、持久化、互斥执行和审计 | 调度框架提供机制，业务控制须自主实现 |
| 手机号搜索 | 本人资料增加可选联系手机号，管理员精确搜索；不引入手机号登录或验证码 | 图片要求，自主界定采集与用途 |
| 全文搜索 | 覆盖公开标题、题面、输入输出说明；不得索引公开不可见题目或隐藏数据 | 图片要求，不强制引入搜索引擎 |
