# Byte Judge 需求收集、分析与确定

> 毕业设计题目：**基于 Spring Cloud 的算法在线评测系统的设计与实现**  
> 文档版本：**V1.1**；更新日期：2026-11-02。  
> 本版依据用户提供的功能树图片重新确定完整范围。图片中的消息、独立运行、竞赛全流程及定时任务均为本期必做；V1.0 中将这些能力延后的安排不再适用。本文描述需求，不代表功能已实现、测试已通过或导师已签字确认。

## 1. 项目背景与目标

算法学习需要阅读题目、编写程序、运行调试、提交评测及复盘记录；算法竞赛还需要报名、按时开放题目、公平计分及赛后练习。只依靠本地样例和人工检查，难以统一运行环境、留存过程和保障竞赛时间边界。本项目面向高校学生、算法学习者及管理员，建设集算法练习、在线评测、个人竞赛和后台管理于一体的 Web 系统。

本期目标如下：

1. 建立“题库检索 → 阅读与切题 → 在线编码 → 自定义运行 → 正式提交 → 自动评测 → 结果与历史回顾”的练习闭环。
2. 建立“管理员组题发布 → 用户发现并报名 → 按时参赛 → 计分排名 → 结算通知 → 赛后练习”的竞赛闭环。
3. 建立题目、竞赛、用户及定时任务管理入口，并通过个人消息通知用户重要业务事件。
4. 在受限环境中编译和执行用户程序，保护隐藏数据，区分用户程序错误和平台故障，保证提交、重判和排名可追溯。
5. 使用 Spring Cloud 的网关、服务发现和服务协作，分离业务与判题职责，支持独立部署、双判题实例和故障恢复演示。

项目定位为**面向高校学习与个人算法竞赛的中小型 OJ**。用户图片中的完整功能是交付边界，开发顺序可以分阶段，但不能以“毕设控制范围”为由把图中功能改为可选。

## 3. 角色、权限与核心场景

### 3.1 利益相关者

| 对象 | 核心诉求 | 对应能力 |
| --- | --- | --- |
| 算法学习者 | 找题方便、代码不丢、运行和提交含义清晰、历史可回看 | 题库、编辑、独立运行、正式评测、个人记录 |
| 参赛者 | 发现比赛、报名清楚、开赛公平、结果及排名可信、赛后复盘 | 竞赛列表、报名、赛内流程、排名、赛后练习、消息 |
| 题目维护者/教师 | 数据和题目正确、竞赛组题保密、发布可控 | 本期统一使用管理员角色，不独立建教师角色 |
| 管理员 | 管理用户、题目、比赛、任务并定位异常 | 后台检索、状态操作、审计、节点和任务记录 |
| 开发者与评审者 | 功能完整、规则一致、Spring Cloud 协作可演示 | 需求追踪、验收标准、部署及故障演示 |

### 3.2 权限矩阵

游客是未登录状态；普通用户与管理员是业务角色；禁用/拉黑是账户状态；判题节点和定时任务使用内部服务身份。

| 操作 | 游客 | 正常普通用户 | 正常管理员 |
| --- | --- | --- | --- |
| 浏览公开题库、已发布竞赛列表及正式排名 | 允许 | 允许 | 允许 |
| 浏览未开始比赛题面、样例、标签或快照 | 不允许 | 不允许，即使已报名 | 管理需要时允许并审计 |
| 比赛进行中读取题面、运行及提交 | 不允许 | 仅已报名该赛者 | 管理身份不自动产生参赛成绩 |
| 已结束且仍发布比赛的赛后题面 | 只读 | 可练习，无需曾报名 | 允许 |
| 公开题库自定义运行及正式提交 | 不允许 | 允许 | 允许 |
| 本人资料、手机号、记录、消息和我的竞赛 | 不允许 | 仅本人 | 仅本人；管理操作使用专门入口 |
| 他人源码、完整手机号、隐藏数据 | 不允许 | 不允许 | 受控管理用途，记录敏感访问审计 |
| 题目/竞赛维护、发布/撤销及重判 | 不允许 | 不允许 | 允许，受状态规则限制 |
| 用户检索、拉黑和解禁 | 不允许 | 不允许 | 仅管理普通用户，不提供网页提权 |
| 定时任务及运行记录管理 | 不允许 | 不允许 | 仅允许白名单任务，不可编辑受保护核心任务 |

禁用后下一次受保护请求必须被拒绝，旧会话失效；仍可按游客浏览公开内容。禁用不取消已经受理的评测或历史成绩。解禁后需重新登录，不能使旧会话恢复。

### 3.3 核心场景

- **日常练习**：全文找题、按难度筛选、切题、编码、自定义输入运行、正式提交、查看判定与历史。
- **个人消息**：查看报名成功、撤销/改期、结算及重判更正等系统通知，标记已读或删除本人消息。
- **完整参赛**：从推荐/历史列表或我的竞赛进入，开赛前报名，开赛后访问题目、运行和提交，赛后查看正式排名并练习。
- **出题办赛**：管理员维护并校验私有题目，绑定不可变快照组赛，发布、改期或撤销；赛前保密，赛后记录保留。
- **后台运维**：检索用户并拉黑/解禁，管理白名单定时任务，查看执行记录，定位异常并重判或恢复。

## 4. 范围确定与可行性分析

### 4.1 本期交付基线

**图片中全部需求及既有核心需求均为 P0 必须实现。** 具体为 FR-01～FR-25、BR-01～BR-15、NFR-01～NFR-13、AR-01～AR-07；功能可以按依赖顺序开发，不能只完成题库而把竞赛、消息、独立运行或定时任务留作扩展。

基础题型仍为单文件、标准输入输出、C++17 / Java 21 / Python 3，全部测试点通过才为 AC。竞赛采用个人 ACM 计分；不实现队伍赛、Rating、封榜、OI 部分得分、SPJ 或交互题。

### 4.2 取舍及业务约束

| 问题 | 本期确定方案 |
| --- | --- |
| 图片完整范围与开发周期 | 完整纳入需求，通过分阶段实现和依赖排序控制进度；功能降级必须由用户重新明确变更 |
| 运行与正式提交混淆 | 独立运行使用用户输入并返回其输出，不调用隐藏数据、不判 AC、不进入学习统计或竞赛罚时 |
| 赛题保密与题库共享 | 正式比赛只能绑定已校验且从未公开的私有快照；发布至结束期间不得另行公开或绑定其他未结束赛事，防止题库/历史绕过保密 |
| 竞赛公平与异步判题 | 使用服务器受理时间判断提交是否在比赛区间内；截止前受理的任务可在结束后完成并参与结算 |
| 历史排名与赛后练习 | 区分普通、竞赛、赛后练习三种正式提交上下文；赛后练习不改变正式榜 |
| 后台任务灵活性与安全 | 管理员只创建预定义白名单处理器的计划，不执行任意 Shell、SQL 或 URL；核心任务受保护 |
| 手机号检索与隐私 | 手机号可选，仅联系字段；管理列表掩码，完整值仅受控详情，不因支持检索引入短信认证 |
| 微服务范围 | 用户、题目、提交、判题及竞赛按职责拆分；消息归用户服务，任务后台作为内部能力，不强拆额外服务 |

### 4.3 现状与差距

既有工程说明和依赖声明提供了用户、前端布局和 Spring Boot 等基础参考，但不能据此认定任何业务已通过验收。题库、判题、竞赛、消息、任务管理及 Spring Cloud 协作都需要按本版建立可运行闭环。

新增竞赛带来时间边界、报名权限、赛题保密、异步结算和排名一致性成本；新增运行、消息和任务管理带来资源配额、事件幂等和后台安全成本。技术原型应优先验证隔离执行、任务恢复、计分和定时任务多实例执行，再补齐页面；不把风险分析当成延期已确定功能的授权。

以下均为本期 P0；编号与《需求规格说明书》保持一致。

| 编号 | 模块 | 需求与业务行为 | 验收条件 |

| FR-09 | 提交历史 | 本人按题目、语言、结果、时间及提交上下文筛选分页，查看源码、版本和轮次 | 改编号不能越权；区分普通练习、比赛正式提交及赛后练习；独立运行不混入正式提交记录 |

| FR-12 | 测试数据与校验 | 管理样例/隐藏数据、顺序和版本；每种启用语言用校验程序验证 | 至少一组样例和一组隐藏数据；当前草稿全部启用语言通过才可发布/绑定发布比赛；修改后旧验证失效 |
| FR-13 | 后台用户管理 | 按用户 ID 精确、完整手机号精确、昵称包含组合 AND 搜索并分页；查看状态、拉黑/解禁普通用户 | 管理列表手机号掩码，完整值仅受控详情；旧会话及时失效；不能网页提权或操作管理员账户 |
| FR-14 | 提交管理与重判 | 管理员按用户、题目、上下文、结果和时间查提交，查看诊断并单条重判 | 原版本和环境固定，旧轮次保留；新非 SE 结果替换有效结果，重判 SE 保留此前非 SE 结果；影响比赛时更正排名并通知 |
| FR-15 | 运行概况 | 查看提交量、队列、运行任务、SE、判题节点健康及相关执行记录 | 失联可被识别，普通用户看不到内部地址；区分业务结果、独立运行和平台指标 |
| FR-16 | 任务恢复 | 对投递失败、失联、超时补偿和有限重试，防重复/过期回写 | 已受理记录不丢，最多额外两次重试，有界收敛 SE；消息、成绩和统计无重复副作用 |
| FR-17 | 我的消息 | 本人消息列表、分页、详情、已读和删除；系统生成报名成功、比赛改期/撤销、结算、重判更正等通知 | 只能读删本人消息，事件重复不重复通知；删除消息不撤销报名/比赛/成绩，不提供用户互发 |
| FR-18 | 我的竞赛 | 展示本人已报名比赛，按状态/时间筛选分页；未开赛显示“未开赛”，赛中显示“开始答题”，赛后提供“竞赛练习/竞赛排名” | 结算中/已结束及撤销有明确反馈；入口受时间和报名权限控制，不能以改 URL 越权 |
| FR-19 | 独立自定义运行 | 题库、赛内、赛后共用受限运行；用户自填输入与代码，各 ≤64 KiB；生成独立 runId，返回本人 stdout/stderr | 正常完成显示“运行完成”而非 AC；不读隐藏数据、不计正式提交/通过数/排名；输出展示各 ≤16 KiB，超限标注截断 |
| FR-20 | 公开竞赛列表 | 推荐/历史比赛、名称及开始时间区间筛选、分页；推荐为已发布未结束比赛按开始时间升序 | 未开赛未报名显示“报名”，已报名显示“已报名”；开赛已报名显示“开始答题”，未报名显示“未报名”；历史可练习/查榜；不含草稿/撤销，非个性化推荐 |
| FR-21 | 竞赛报名 | 正常登录用户在已发布比赛开始前报名；报名幂等并发安全 | 仅服务器 `now < start` 允许；不支持开赛后补报名；开赛未报名显示不可参赛，重复报名不重复通知 |
| FR-22 | 比赛全流程 | 已报名用户在赛中访问绑定快照、切题、编辑、独立运行、正式提交和查询结果 | 比赛开始前题面/样例/标签/快照保密；正式受理时段为服务器 `[start,end)`；截止前受理可赛后完成并计入结算 |
| FR-23 | 赛后练习及正式排名 | 个人 ACM 实时榜/正式排名与成绩详情；赛后已发布比赛正常用户可练习，无需报名，游客只读 | 按解题数、罚时、最后 AC 相对时间排序，同指标并列；无正式提交无名次；赛后练习不改正式榜；重判更正可追溯 |
| FR-24 | 后台竞赛管理 | 按名称、创建时间筛选分页，竞赛增删改查、发布、撤销；绑定完整已校验且从未公开的私有快照 | 仅赛前可改/撤销，改期保留报名并通知；开赛后冻结时间/题集/规则；仅未发布且无报名提交可删除，带记录比赛不可销毁 |
| FR-25 | 后台定时任务管理 | 任务列表/详情、创建、修改、删除、启停与运行记录；六字段 cron，时区 Asia/Shanghai | 内置核心任务受保护；自定义计划只能调用白名单处理器并校验参数；不允许任意 Shell/SQL/URL；多实例不重复业务副作用 |

测试数据以逐项管理为本期要求，ZIP 批量导入仍可后续扩展。定时任务“增删改查”指管理业务计划和执行记录，不授权编辑任意系统程序。

## 6. 核心用例与用户体验

### 6.1 UC-01 题库练习与独立运行

- 用户全文搜索并筛选题目，阅读详情，切换题目/语言并编辑；游客可阅读和编辑，运行或提交时提示登录。
- 自定义运行使用用户输入和独立 runId；运行输出只供本人查看，不表明通过测试，不写入正式提交和竞赛计分。
- 正式提交携带阅读版本和提交上下文；成功后凭提交编号异步查询，历史保留。
- 登录过期保留本账户草稿；游客登录时确认导入草稿，若账户已有草稿不得静默覆盖。切题、刷新和网络重试不能导致代码丢失或重复提交。

### 6.2 UC-02 发布题目及比赛

- 管理员创建题目草稿，维护题面、样例、隐藏数据、语言及限制，通过分语言校验。
- 管理员创建比赛、设定开始/结束时间和规则、绑定完整不可变私有快照后发布；正式赛题快照从未公开到题库或历史比赛。
- 赛前变更需重新满足发布校验，已报名用户收到改期或撤销消息；开赛后冻结时间、题集和计分规则。

### 6.3 UC-03 报名、参赛、排名及赛后练习

- 用户从推荐比赛、历史列表或我的竞赛进入；报名仅在已发布且服务器时间早于开始时允许。
- 赛中已报名者读取题面、切题、运行、正式提交并查看结果；未报名者不得借接口或搜索读取受保护赛题。
- 结束时关闭赛内正式受理；已受理任务继续判题和结算。未收敛时显示“结算中”，完成后提供正式结果与通知。
- 用户赛后查看正式榜和练习；赛后练习另立上下文，不影响正式榜，题目不必自动公开到题库。

### 6.4 UC-04 消息与后台运行管理

- 系统事件产生本人通知，用户分页查看、进入详情、标为已读或删除；不提供私信聊天。
- 管理员按用户 ID、手机号、昵称检索拉黑/解禁，按名称/创建时间管理竞赛。
- 管理员建立白名单定时计划，查看执行结果；核心保护任务不可任意停用。集群重复触发不造成重复报名、通知或结算。

### 6.5 通用交互要求

题面与编辑区在桌面端同页可见；切题/语言保存对应草稿。列表有加载、空、失败和分页反馈，错误不清空合法输入。比赛页面展示服务器校准的时间和阶段，按钮随权限/阶段变化，但最终由服务端判定。排队显示已等待时间；断网只改变连接提示，不把未知结果改成失败。结果用中文及缩写、ms/MiB 单位，不只靠颜色；核心按钮可键盘聚焦。发布、撤销、拉黑、删除、重判等操作确认具体对象和影响。

## 7. 业务规则

### 7.1 BR-01 生命周期与判定

评测轮次采用 `WAITING → RUNNING → FINISHED`；可恢复故障可返回等待并增加尝试编号，最多三次尝试。截止或不可恢复平台故障进入 SE，终态不能被迟到回调翻转；重判创建新轮次，不改写旧历史。

| 判定 | 本项目含义 |
| --- | --- |
| AC | 全部测试点正常且输出匹配 |
| WA | 正常运行、未超限，但输出不匹配 |
| CE | 编译/语法检查失败或用户编译过程超限 |
| TLE | 单测试点 CPU 或墙钟超限 |
| MLE | 有可信内存限额触发证据 |
| RE | 异常退出、违反执行或进程限制，且无更明确超限证据 |
| OLE | 运行输出任一路超过限额；恰好达到仍允许 |
| SE | 数据/环境/沙箱/节点故障或恢复与整体截止耗尽等平台错误 |

独立运行复用失败原因和资源限制，但成功结果显示“运行完成”，不产生 AC/WA 答案判定。

### 7.2 BR-02～BR-04 程序、比较及资源

- **BR-02 程序模型**：三语言单文件，标准输入输出；Java 为无自定义 package 的 Main。编译参数由平台固定，不接受任意入口、依赖或命令。编译和每个测试点隔离，文件/进程不得跨任务残留；实际制品版本公开并固定。
- **BR-03 输出比较**：仅以 ASCII 空白 `0x09～0x0D`、`0x20` 分隔 token，按字节序列、区分大小写比较；忽略首尾和连续分隔符，不做浮点容差或数值等价。`1` 与 `1.0` 不同。独立运行无标准答案比较。
- **BR-04 汇总**：正式评测按固定测试顺序首错停止，后续记未执行；无部分得分。同点多项证据先辨基础设施故障，再按 MLE、OLE、TLE、RE、WA 归类。时间取测试点进程组 CPU，内存含运行时及子进程峰值；展示已执行点各自最大值，未知显示“—”。

### 7.3 BR-05 资源与防滥用

| 项目 | 本期初始规则 |
| --- | --- |
| 源码及自定义输入 | 源码 UTF-8 ≤64 KiB；独立运行自定义输入 ≤64 KiB，允许空输入 |
| 新提交及运行配额 | 同账户新正式提交与RUN共用至少3秒受理间隔；正式初判与RUN合计最多3个活跃任务；幂等确认不重复占额 |
| 编译/语法检查 | 墙钟 ≤30 秒，内存 ≤1024 MiB，进程/线程 ≤128，输出/错误各 ≤1 MiB |
| 单测试点默认时间 | CPU 2 秒、墙钟 5 秒，可按语言/题目配置并受部署范围限制 |
| 默认运行内存 | C++/Python 256 MiB、Java 512 MiB，包含运行时；三语言分别校准 |
| 输出 | 标准输出与错误各 ≤1 MiB；前端诊断/独立运行输出各最多展示 16 KiB并标记截断 |
| 数据 | 一组以上样例、一组以上隐藏数据，合计 ≤20 组，单组输入/期望输出各 ≤1 MiB |
| 重试和截止 | 每轮最多额外两次平台故障重试；所有等待区间累计 ≤300 秒；执行及整轮有绝对截止 |

独立运行与正式提交共享账户配额；管理员发布校验使用独立受限调度，但同样不能绕过隔离和隐藏数据保护。单次执行预算按编译上限、测试点墙钟之和和有限清理缓冲计算；重试不重置累计等待预算，整轮超时收敛 SE。可写磁盘/文件数及具体配置边界、计算式见规格说明书。

### 7.4 BR-06～BR-09 版本、一致性与历史

- **BR-06 版本与幂等**：提交固定题目/数据/语言环境、资源配置、源码及上下文。新请求必须匹配当前允许版本；同用户同请求标识同载荷返回原编号，异载荷冲突。先鉴权再确认幂等，之后校验新请求的发布和配额。先持久化可恢复任务再返回成功。
- **BR-07 统计**：普通练习、赛后练习、竞赛正式提交均可计个人累计，独立运行和管理员校验不计；正式受理编号含 SE，有效 AC 计 AC 数，题目身份去重计通过题数。题目通过率为有效 AC / 有效非 SE 的已完成提交，分母零为“—”。比赛榜只用该赛 `[start,end)` 受理的正式提交，不能混入其他上下文。
- **BR-08 删除与禁用**：下架/逻辑删除阻止新题库受理，不取消已受理任务，不销毁历史及竞赛快照。用户禁用不撤销历史成绩。本人删除消息仅改变可见性，不删除业务事实。历史在毕设运行期保留，临时执行文件及时清理，审计至少180天。
- **BR-09 重判**：每条提交不并行创建重判，运行中保留旧有效结果。新非 SE 终态替换有效结果；新 SE 保留旧非 SE 结果并另显本次失败。重复消息不重复统计；影响比赛的有效更正重算正式榜、记录原因并通知。

### 7.5 BR-10 竞赛生命周期、版本及保密

管理生命周期包含草稿、发布、撤销；时间阶段由服务器时间确定，为未开始、进行中、已结束；已结束且仍有赛时受理待判任务时附加显示“结算中”。正式赛事发布绑定已完整校验、从未公开的不可变私有题目快照。赛事发布至结束期间题目不得另行公开到题库，也不得绑定其他未结束赛事；不能通过题库、历史、消息、搜索或数据接口绕过保密。

开赛前不向普通用户返回题面、样例、标签或快照，即使已报名；赛中仅已报名者可取题面；赛后仍发布的比赛对游客只读，对正常用户开放练习，不要求自动公开题库。

只在开赛前允许修改/撤销；改期保留报名并通知。开赛后冻结开始/结束时间、题集及计分规则；不能删除有报名、提交或成绩的比赛。只有未发布且无报名/提交的比赛可删除。状态与权限以服务器规则即时判断，不依赖定时任务是否准点执行。

### 7.6 BR-11 报名与正式受理时间

报名要求正常登录、比赛已发布且服务器 `now < start`；同一用户同赛只保留一次有效报名，重复请求幂等。不开放开赛后补报名，这是本项目规则，不是竞品共识。竞赛正式提交只在已报名且服务器受理时间满足 `[start,end)` 时成立；恰好开赛可提交、恰好结束拒绝。客户端倒计时不决定资格。截止前已受理提交即使赛后完成仍属于赛内正式成绩。

### 7.7 BR-12 计分、正式榜及结算

个人 ACM 排名依次按解题数降序、总罚时升序、最后 AC 的相对时间升序；相同指标并列。每题只取首个有效 AC，罚时为相对开赛的首 AC 分钟数，加该 AC 前 WA/TLE/MLE/RE/OLE 次数乘20分钟；CE、SE、自定义运行不罚。未 AC 题不贡献解题数和罚时。

报名但无正式提交者显示“未参赛/无名次”；有正式提交而零 AC 者参与排名，按零解题、零罚时并列。实时榜不封榜。比赛结束停止赛内受理，待此前提交均收敛后结算；结算前显示“结算中”，不能把待判任务算作失败。赛后练习另记上下文，不改变正式榜。管理员对原版本的有效重判可更正历史正式榜并审计、通知，仍按原赛内受理时间和规则重算。

### 7.8 BR-13 独立运行边界

运行在题库、比赛、赛后场景使用同一受限能力；读取题目时先按上下文验证权限。只处理用户本次输入，不读取隐藏数据、无预期输出比较，返回独立 runId、阶段、资源、本人标准输出及错误。运行完成不等于通过题目，不进入正式提交历史、个人统计、排名或罚时。运行输出与正式隐藏测试输出的公开策略必须分别处理。普通、赛内正式、赛后练习、独立运行使用持久类型标识，不依靠临时页面位置区分。

### 7.9 BR-14 系统消息和手机号

消息仅由报名成功、改期/撤销、结算、有效重判更正等系统事件产生；事件与接收者幂等，用户只可读/标记/删除本人消息，不提供互发。通知失败应可恢复，不因删除消息撤销事件。

手机号为可选联系字段，7～15位 ASCII 数字，可前置 `+`；不要求唯一、不代表已验证身份，不提供短信登录/找回。管理员可按完整值精确查找；列表掩码，完整值仅受控详情及本人可见，公开接口及日志不泄漏。

### 7.10 BR-15 定时任务管理

管理员可管理预定义白名单处理器的自定义计划，填写名称、六字段 cron、Asia/Shanghai 时区和合法参数，支持列表、详情、增改删、启停及运行记录。不得输入任意 Shell、SQL、代码或 URL。内置恢复/清理/结算等核心任务受保护，不能通过普通任务界面删除或任意停用。

多实例需有调度/业务幂等保障，不能重复发送同一通知、重复结算或重复恢复任务。运行记录包含计划、触发/起止时间、状态及有限错误原因。竞赛是否开始/结束以服务器时间直接判定，定时器延迟不得延长报名或比赛。

| 对象 | 必需信息 | 关键约束 |

| 独立运行 | runId、本人、上下文、源码/输入、状态、资源、有限输出及截止 | 与正式提交分离，不形成题目通过和正式成绩 |
| 竞赛与题集 | 名称、创建时间、发布状态、起止时间、规则、私有快照顺序和管理版本 | 发布前校验、赛前保密、比赛结束前不得另行公开或跨赛复用 |
| 报名与排名 | 用户/比赛唯一报名、报名时间、解题和罚时明细、正式榜版本 | 排名可按赛内有效提交重建，赛后练习不写正式榜 |
| 系统消息 | 接收者、事件标识、内容、关联对象、已读/删除、时间 | 本人可见，删除不删除业务事件，重复事件不重复投递 |
| 定时任务与运行记录 | 白名单处理器、参数、cron、状态、核心保护标记、触发和结果 | 多实例不重复业务副作用，不能从参数升级成任意执行 |
| 审计 | 操作人/服务身份、对象、时间、结果、追踪编号 | 发布/撤销/拉黑/删除/重判/任务变更及敏感访问留痕 |

本期不采集身份证号、院系或学号等无关数据。完整手机号、他人源码、隐藏数据和内部日志仅在明确权限下访问。竞赛快照、历史提交与正式榜的关联在本期运行期间不得被物理删除破坏。

## 9. 非功能需求与验收方向

以下均是待验证目标。参考环境为 Linux、服务端至少8 vCPU/16 GiB、同一局域网客户端；性能数据包含10,000道题目元数据和100,000条提交，不等于人工编制同等数量可运行题。详细负载、边界和验收用例见规格说明书。

| 编号 | 类别 | 本期要求 |
| --- | --- | --- |
| NFR-01 | 正确性 | 三语言及八类评测结果可复现；全文检索权限、比赛时间边界、报名幂等、计分并列、赛后隔离、消息与任务副作用有验收数据 |
| NFR-02 | 查询性能与隔离 | 50登录会话、总20 RPS连续5分钟的规定混合查询，P95≤1秒、非预期错误率<1%；判题积压时公开题库及历史仍可用 |
| NFR-03 | 受理性能 | 20账户10秒内各交一次，按规定重复批次形成样本；P95≤2秒；所有成功受理最终可追踪且不丢失 |
| NFR-04 | 评测与过载 | 空闲节点参考小程序≤30秒；等待、执行、重试和整体轮次均有截止，独立运行不能耗尽正式评测和业务服务预算 |
| NFR-05 | 执行隔离 | 编译/运行非特权，限CPU/内存/进程/输出/可写磁盘/文件数/时间，无外网及业务网络、密钥和敏感宿主挂载；跨任务文件不可读 |
| NFR-06 | 应用与管理安全 | 逐接口身份/资源/比赛资格校验；会话撤销、CSRF/XSS防护；手机号掩码；定时任务无任意命令执行；对外HTTPS |
| NFR-07 | 故障恢复 | 节点失联≤60秒识别；健康节点有容量时≤120秒重排或明确失败；通知/结算/任务重复触发不重复副作用 |
| NFR-08 | 持久化恢复 | 重启保留用户、题目/比赛快照、报名、提交、成绩、消息、任务和审计；备份并完成隔离环境恢复验证 |
| NFR-09 | 易用与兼容 | Chrome/Edge/Firefox测试稳定版完成题库、运行、参赛、消息及管理全旅程；加载/空/错误/倒计时/草稿/结果反馈一致 |
| NFR-10 | 可维护与观察 | 部署/接口/限额/规则文档完整；按请求、提交、比赛、消息事件和任务运行编号定位问题；指标和内部日志受保护 |
| NFR-11 | 竞赛一致性 | 50账户开赛前报名唯一可查；start/end等值由服务器受理时刻确定；有效结果5秒内更新榜，乱序、迟到、重判按正式记录重算 |
| NFR-12 | 独立运行 | 三语言固定参考程序空闲时每次30秒内完成，受理P95≤2秒；与正式初判共享配额，输出/记录/截止有界且无隐藏数据访问 |
| NFR-13 | 消息与调度可靠性 | 正常设施下事件10秒内生成唯一消息、恢复后60秒内补偿；同计划触发单一有效执行者，最多3次尝试，无重复业务副作用 |

“使用容器”“引入搜索组件”或“引入 Spring Cloud”本身都不是通过证据。应验证限制、搜索范围、事件一致性、竞赛边界及跨服务协作实际生效。

## 10. Spring Cloud 架构约束

Spring Cloud 官方提供路由、服务发现、服务间调用、配置等分布式能力，本项目据此确定必要协作约束。[来源：Spring Cloud 官方概览](https://spring.io/projects/spring-cloud/)

| 编号 | 约束 | 验收行为 |
| --- | --- | --- |
| AR-01 | 统一网关 | 外部业务经网关路由；管理/判题/任务内部接口不依赖隐藏URL保护 |
| AR-02 | 核心职责分离 | 用户、题目、提交、判题及网关独立部署；管理接口归各业务服务，沙箱为受限执行组件 |
| AR-03 | 注册发现和配置 | 服务发现不硬编码单实例；环境配置外置，设计阶段校验Boot/Cloud兼容性 |
| AR-04 | 身份一致 | 沿用Session+Cookie方向，共享会话/账户状态，退出改密拉黑及时撤销；业务服务不信任客户端伪造身份头 |
| AR-05 | 异步与容错 | 正式评测、独立运行及事件通知有可恢复安排；持久化/投递补偿、幂等回写、超时收敛 |
| AR-06 | 双节点和观察 | 两判题实例均实际处理任务，单节点停止后恢复，题库及历史可用；关联轮次/尝试/节点日志 |
| AR-07 | 竞赛与新增业务归属 | 竞赛作为独立服务承接报名、阶段、资格和正式计分；消息归用户服务，任务后台为受保护内部管理能力，无需强拆额外服务 |

题目全文搜索可由适合项目规模的数据库能力或搜索组件实现，不强制 Elasticsearch。比赛时间和权限不能依赖异步定时器更新；提交服务与竞赛服务需对受理时点、资格、题目快照及成绩变更建立一致契约。
