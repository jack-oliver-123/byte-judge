# B 端题目草稿编辑与并发保存设计

状态：已确认并整理为[规格 003](../specs/003-admin-problem-draft-edit.md)；任务 [Issue #21](https://github.com/jack-oliver-123/byte-judge/issues/21)，尚未开始实现。

依据：[规格 002](../specs/002-problem-draft-management.md)、[草稿接口](../backend/problem-draft-api.md)、[领域词汇表](../../GLOSSARY.md)。

## 已确认决策

2026-11-12，第一轮 Q1～Q3 全部按推荐确认：

1. 本次范围为草稿字段编辑、保存、并发冲突处理和未保存内容保护。测试数据仅展示现有清单，上传与发布校验留待后续。
2. 使用手动保存，不做后台自动提交。页面区分有未保存修改、保存中、已保存和保存失败。
3. 新增独立编辑页，从题库列表或详情进入，支持直接地址访问和刷新加载；现有详情抽屉继续用于快速查看。

2026-11-12，第二轮 Q4～Q6 全部按推荐确认：

4. 冲突时保留全部本地输入，对照本地内容与服务器最新内容，由管理员决定合并结果；确认后以已查看的服务器修订号再次保存，再次竞争仍提示冲突。不自动覆盖或直接换修订号重试。
5. 当前标签页自动暂存未保存输入，与服务器保存状态分开显示；按管理员账户和题目隔离，同账户返回时提示恢复，主动退出或切换账户时清除。站内离开提醒，不承诺关闭标签页后恢复。恢复细节见第 7、10 项。
6. 题面、输入说明、输出说明采用 Markdown 源文编辑与基本安全预览，支持代码块、列表和表格，禁止原始 HTML 执行。公式、图片上传、富文本工具栏留待后续；C 端展示应遵守同一内容约定，C 端实现不在本次范围内。

2026-11-12，第三轮 Q7～Q10 全部按推荐确认：

7. 恢复暂存前先读取服务器最新草稿。暂存依据的修订号相同则提示恢复；不同则进入差异对照，不把旧暂存直接套用到最新修订号。恢复后仍为未保存，不自动提交。
8. 保存请求期间暂时禁用表单和重复保存；成功留在编辑页并更新修订号，失败解锁且保留输入。没有修改时禁用保存。
9. 网络中断等无法判断是否接受保存的情况显示“保存结果待确认”，保留本地内容并先回读服务器。可编辑内容与本地一致则提示已同步；服务器仍为原修订且内容不同则允许重试；出现内容不同的新修订则进入冲突处理。回读失败继续保留内容，不自动重复提交。不能据内容一致宣称本次请求必然已被接受。
10. 登录过期先暂存，再提示管理员点击重新登录并携带返回编辑页位置。同账户登录后提示恢复，其他账户登录清除原暂存，不自动保存。暂存失败时停留当前页、提示并允许复制内容，避免直接跳转导致丢失。

2026-11-12，第四轮 Q11～Q14 全部按推荐确认：

11. 冲突按字段对照，每个不同字段选择本地或服务器内容，回到编辑表单检查后手动保存；题面和两项说明分别按完整字段选择，不做逐行自动合并。相同字段不必选择，差异未处理完不能提交。
12. 输入变化后 1 秒内暂存。暂存不可用时仍允许编辑及手动保存，持续提示并提供复制全部编辑内容、可选中文本两种出口。站内离开需确认，刷新或关闭使用浏览器离开提醒。
13. Markdown 预览支持标题、段落、列表、引用、代码块、表格和普通链接；图片显示占位提示，不加载内容。原始 HTML 按文本处理，链接仅允许安全网页地址。
14. 编辑途中题目不存在或权限失效时停止保存与自动重试，明确提示；账户未切换时保留当前输入供复制，不自动另建题目。初次无法读取题目时只展示错误与返回入口。

## 现有契约约束

- 题目草稿可以不完整；不将发布必填规则用于草稿保存。
- PATCH 保存完整可编辑字段集及 expectedRevision，可空字段显式传 null。
- 接受保存后递增修订号，包含无实质变化的保存。
- 保存冲突返回 HTTP 409、业务码 40910，以及当前草稿及修订号。
- 文件清单变化也递增草稿修订号。
- 领域术语沿用题目、题目草稿、题目版本和测试数据；不将草稿修订号称为发布版本号。

## 目标与实施方式

管理员可从现有题库进入独立页面，补全草稿、明确保存结果，并在竞争、断网、刷新或登录失效时保护输入。成功标准是编辑内容真实持久化、冲突不静默覆盖、暂存不被误认为服务器保存。

已选方式是独立页面、手动保存、按字段人工处理冲突。相较继续扩展详情抽屉，独立页面能容纳长题面及差异对照并支持直接访问；相较后台自动提交，手动保存能清楚界定修订变化；相较自动逐行合并，按字段选择减少误合并规则和额外复杂度。以上取舍分别在 Q2、Q3、Q11 确认。

沿用 Vue、Pinia、Vue Router、shadcn/vue 与现有主题。实现只补受影响前端链路；不重构认证体系、不改后端业务接口、不实现上传、发布、下架或 C 端页面。Markdown 存储仍是普通字符串，编辑与预览约定不等于新增发布校验规则。

## 编辑页面及字段

以下是基于已确认需求的实现细化，提交本设计一并审阅：

- 路由采用 `/problems/:id/edit`，实际部署地址带 `/admin/` 基址；元信息要求管理员。列表及详情提供编辑入口，保留现有只读详情抽屉。
- 显示题号、草稿修订号、服务器更新时间，以及相互独立的保存状态和本地暂存状态。修订号不能标为发布版本。
- 表单分为基本信息、题面及说明、资源限制；测试数据清单只读。窄屏使用编辑/预览切换，避免长文双栏挤压。
- 可编辑字段仅包含 title、statement、inputDescription、outputDescription、difficulty、tags、timeLimitCpuMs、timeLimitWallMs、memoryLimitMiB。资源单位明确为 ms、MiB，数字填写整数，允许留空；草稿不强制三项资源同时填写。
- 标题去首尾 Unicode 空白后为 1～100 个码点；标签最多 5 个，每个去首尾空白后为 1～20 个码点；不自行增加标签去重规则。题面和两项说明原文保留，合计最多 102400 个 UTF-8 字节，不按字符数替代。
- CPU 为 100～10000 ms，墙钟为 100～30000 ms，内存为 64～2048 MiB；CPU 和墙钟均存在时墙钟不得小于 CPU。不套用发布必填要求。
- 空白文本框无内容时提交 null，保留非空题面原有空白；标签无值发送空数组，难度未选及未填数字发送 null；请求始终携带全部字段。比较脏状态及回读同步状态时采用同样的字段规范化，避免 null/空输入和标题规范化造成假差异。
- 前端可判断的字段错误就近展示并保留输入。后端 400 当前没有结构化字段错误清单，无法定位的错误用表单级提示与 requestId 展示，不依赖解析英文错误消息。

字段事实以 [DraftContent](../../byte-judge-backend/byte-judge-models/byte-judge-problem-model/src/main/java/com/jack/bytejudge/problem/admin/domain/model/DraftContent.java) 与 [草稿接口](../backend/problem-draft-api.md) 为准。

## 保存与异常状态

| 状态或结果 | 行为 |
| --- | --- |
| 初次加载 | 验证当前管理员身份并读取详情；未成功前不显示可编辑表单，不恢复其他账户暂存 |
| 内容未变 | 保存禁用；本地暂存不能使页面显示为已保存 |
| 有修改 | 允许保存，按规则暂存；本地校验失败时定位错误，不发 PATCH |
| 保存中 | 固定本次请求内容及 expectedRevision，禁用编辑和重复保存；离开仍受保护 |
| 成功 | 用服务端返回内容、清单与 revision 更新基线，清理该题暂存，显示已保存并留在当前页 |
| 400 | 解锁并保留输入，显示校验错误 |
| 409 / 40910 | 保留本地输入，使用返回最新详情进入字段对照，不自动重试 |
| 网络异常、响应损坏或无法确定是否提交 | 显示结果待确认，先 GET 回读，不自动重发 PATCH；不能仅凭 5xx 保证写入未发生 |
| 待确认回读失败 | 保留请求快照与当前内容，继续禁用保存和编辑，允许复制、重新确认结果或经提醒离开 |
| 401 | 保留输入与暂存，停止业务写入，显示重新登录入口，登录成功返回但不自动保存 |
| 403 / 40300 | 停止保存，保留同账户输入供复制；不当作会话过期无限重定向 |
| 403 / 40301 | 提示安全校验失效，更新 CSRF 后允许管理员手动重试，不自动重放写请求 |
| 404 | 不再保存或重试，提示题目已不可编辑，保留同账户已加载输入供复制 |

结果待确认的回读与本次冻结请求的规范化字段比较：内容一致则更新基线并显示“已与服务器同步”，不宣称该次写请求必然成功；内容不同且修订未变则解锁允许重试；内容不同且修订已变则进入冲突流程。回读发现会话、权限或题目失效时转入相应状态。

保存通过现有统一响应请求层，所有写操作获取并发送有效 CSRF 头，不以身份请求头代替会话。成功退出、账户改变时清理暂存与内存编辑内容，取消未完成读取并忽略旧请求迟到结果，避免重新填回旧账户内容。保存正在进行时阻止普通站内跳转，主动退出须明确确认后执行。

## 冲突对照与恢复

1. 保留本地字段快照，展示服务器当前修订及逐字段差异；长文本两侧展示原文，不把差异内容当作 HTML。
2. 每个不同字段显式选择本地或服务器值。标签作为整体字段；三个资源值分别选择，合并后仍执行联动校验。
3. 全部选择完成后，管理员确认回到表单，以所查看的服务器详情为基线，所选内容作为待保存内容，不立即发请求。
4. 若合并后内容等同服务器则显示已同步，无需额外保存；否则手动 PATCH 并携带所查看的修订。再次竞争重复相同流程。
5. 若仅清单或其他元信息变动导致修订变化，显示变动提示与最新只读清单，即使没有可编辑字段差异，也需确认最新修订后才能继续。不得静默换修订号。
6. 对照过程中取消操作保留本地输入与冲突状态，可继续处理或复制后离开；采用服务器内容并放弃本地修改须明确确认。

暂存使用当前标签页的 sessionStorage，按 userId + problemId 隔离，包含格式版本、题目/草稿身份、基线修订和本地字段；不存密码或 CSRF。输入后 1 秒内写入，站内离开、刷新、登录跳转前尽力同步写入。损坏或不兼容暂存提示不可恢复，不把损坏内容提交。

恢复前必须重新获取当前身份和服务器详情。同修订提示恢复或放弃暂存；不同修订进入相同对照流程。相同内容则提示已同步并清除冗余暂存。不同 draftId 不直接套用旧暂存，提示不兼容并允许同账户复制。暂存失败持续提醒，正常手动保存仍可使用；浏览器关闭提醒依浏览器能力工作，不承诺拦截所有关闭或崩溃。

普通站内离开确认后保留可用暂存以便返回；明确放弃暂存、成功保存、主动退出或识别到账户改变时清理对应内容。复制出口包含全部可编辑字段及题号，不包含认证信息；权限变化后只用于已加载内容的人工保护，不用于绕过后端访问控制。

## Markdown 约定

- 支持 Q13 确认的基础语法，保留原文；预览在本地完成，不把草稿发送给外部渲染服务。
- 原始 HTML 转义显示，不执行脚本；不启用任意 HTML、嵌入媒体或公式插件。代码块按文本显示，本次不要求语法高亮。
- 普通链接只允许 http/https，拒绝脚本、data 等地址；新窗口打开时隔离 opener。图片显示可读占位，不生成 img 请求，也不隐式加载嵌套图片。
- 选择成熟解析器，输出经白名单清理后渲染；具体包与补丁版本由实现阶段确认，不自制 Markdown 解析器。当前工程尚未安装 Markdown 渲染依赖。
- C 端后续需保持相同源码语义，允许以后明确扩展；本次不修改 C 端或批量重写已存内容。

| 场景 | 可观察结果 |

| 暂存和剪贴板不可用 | 持续提示，可手动保存及选择文本；不自动丢弃输入或跳转 |
| 路由离开、刷新、主动退出及迟到请求 | 提醒符合规则，退出清理，迟到响应不恢复旧账户内容 |
| 编辑途中 404/403 与初次加载失败 | 停止保存，已加载输入可复制；初次失败不呈现空白可保存表单 |
| Markdown 代码、表格、HTML、危险链接与图片 | 基础语法可读，原始 HTML 不执行，危险链接不可用，无图片请求 |
| 页面质量 | 保留列表筛选与分页，键盘可达、标签明确，窄屏能编辑/预览，错误可见 |

验证采用针对本次逻辑的自动化行为测试，以及浏览器真实接口联调；模拟断网和响应丢失用于异常场景。执行现有类型检查与构建，lint 使用不自动修复的受影响文件检查。前端当前无测试脚本，具体行为测试工具在实现计划中选定，不将新增完整测试平台作为功能前提。
