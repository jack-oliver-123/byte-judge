# 成熟 OJ 系统调研

调研日期：2026-11-02。用途：为《基于 Spring Cloud 的算法在线评测系统的设计与实现》提供需求依据。

## 1. 调研方法与边界

本次采用竞品文档分析法，选择洛谷、LeetCode、Codeforces 三种公开在线平台，以及 QingdaoU OnlineJudge、HOJ 两种可部署的开源系统，覆盖算法训练、编码体验、竞赛和自建 OJ 等不同侧重点。仅采用官方帮助、官方页面、官方 API 文档和项目维护者仓库；没有进行用户访谈、问卷、注册后的完整操作或实际部署压测。

下文“已核实”表示官方来源明确描述或公开页面展示该能力；开源项目的能力是维护者文档所声明的能力，不代表本次已运行验证。未找到证据的项目记为“本次未核实”，不能据此断言平台不支持。各平台采用的语言版本、收费策略、性能和内部服务架构不作为本项目的既定事实。

## 3. 与需求相关的证据

### 3.1 题库与题面

洛谷官方帮助明确给出按关键词、难度和标签找题的方式；Codeforces 公开题库也展示难度范围与标签筛选。两者共同说明题库不应只有无分类的题目列表。[洛谷常见问题](https://help.luogu.com.cn/manual/luogu/faq)、[Codeforces 题库](https://codeforces.com/problemset)

Codeforces 的 Watermelon 题面公开展示标准输入输出、样例、每测试点时间和内存限制。本项目可采用同类完整程序题，但该题的具体限制不应直接作为所有题目的限制。[Codeforces 4A 题面](https://codeforces.com/problemset/problem/4/A)

### 3.2 编辑、自测与提交

LeetCode 官方指南分别说明运行自定义测试与提交正式评测，并说明提交进入历史记录；洛谷说明在线 IDE 的限制可能不同于正式评测。由此推导，本项目需要明确标注自测结果不等于通过全部测试。[LeetCode 编码练习指南](https://support.leetcode.com/hc/en-us/articles/360012016874-Start-your-Coding-Practice)、[洛谷常见问题](https://help.luogu.com.cn/manual/luogu/faq)

### 3.3 判题与结果

Codeforces 的提交对象区分编译错误、运行错误、答案错误、超时、超内存、测试中等状态，并保存资源消耗。由此推导，本项目需要结构化结果和可查询的任务状态，不能只返回“通过/失败”。[Codeforces API 对象文档](https://codeforces.com/apiHelp/objects)

### 3.4 题目维护与权限

洛谷支持创建题目、上传数据和配置测试点限制；QingdaoU 文档列出不同管理员权限。由此推导，本项目应提供题面、数据和限制的维护入口，并对题目发布及敏感数据访问做后端校验。两种管理员是否均需引入本项目，应由毕设规模决定。[洛谷题目指南](https://help.luogu.com.cn/manual/luogu/problem/)、[QingdaoU 官方 README](https://github.com/QingdaoU/OnlineJudge/blob/master/README-CN.md)

### 3.5 扩展能力的成本

HOJ 已覆盖题单、团队、讨论及多种评测形式；洛谷对远程评测明确提示结果与可用性依赖目标网站。由此推导，本项目首期应优先完成本地普通题判题闭环，竞赛和社区分期建设，远程判题不作为核心验收依赖。[HOJ 官方 README](https://github.com/HimitZH/HOJ)、[洛谷 RemoteJudge 说明](https://help.luogu.com.cn/manual/luogu/problem/remote-judge)

## 4. 面向本毕设的取舍建议

以下是基于上述竞品共性与毕业设计规模作出的项目建议，不是已完成的用户调查结论；最终范围以 [01.需求文档.md](01.需求文档.md) 为准。

| 建议层级 | 内容 | 理由 |
| --- | --- | --- |
| 首期必需 | 注册登录、角色权限、题库筛选、题目详情、在线编辑、正式提交、异步判题、状态与历史、题目和测试数据管理、个人做题统计。 | 形成学生练习和管理员维护的完整闭环。 |
| 首期技术约束 | Spring Cloud 服务协作、判题执行与业务服务隔离、资源限制、任务持久化与恢复、访问控制、操作日志。 | 与题目所要求的分布式实现相符，并使异常和安全边界可验证。具体技术方案另行设计。 |
| 可控增强 | 自定义输入自测、收藏或题单、基础排名、官方题解、公告。 | 改善学习体验，依赖核心题库和提交能力，适合核心稳定后实施。 |
| 后续扩展 | 完整竞赛与封榜、团队教学、社区讨论、代码查重、复杂 SPJ/交互题、远程判题、AI 辅导。 | 独立规则或外部依赖较多，容易扩大首期工作量。 |

首期建议支持 Java、C++、Python 3 三种语言，采用标准输入输出、普通输出比较、所有测试点通过才判 AC 的模式。这是项目范围选择，不能写成全部竞品的一致做法。多语言的编译/运行版本、资源口径和比较规则需要在需求与设计中明确。
